# 可复现验证任务

这些是测试题，不是已取得的效果证明。比较时固定模型、推理设置、工具、任务原文和时间/调用预算；使用独立会话，分别运行不用 Skill、当前 Skill、其他相关 Skill。记录版本或 commit。不要先展示期望答案，也不要将一次输出当作稳定结论。

## A · 消费类首页与流程

> 为城市散步路线 App 设计 390px 手机 HTML。用户选择时长和起点后浏览三条路线，查看其中一条详情并收藏；返回列表后收藏状态保留。每条路线包含距离、时间、路面条件与适合人群。品牌定位是轻松、可信的城市探索。使用虚构路线，明确其演示性质。不指定配色与卡片形式，交付可运行文件。

检查：路线是否容易比较；主要动作是否明确；返回与收藏是否工作；视觉是否体现产品而非通用仪表盘；文字是否可读。

## B · 表单与恢复

> 为设备维修预约设计 375px 手机 HTML。用户填写设备、故障说明、联系方式与时间段，检查摘要后提交。必须能返回修改并保留输入，校验缺失项，并提供可触发的模拟失败与重试。沿用已有工程；没有工程则生成独立 HTML。无需登录和真实后台。

检查：错误是否定位到字段；输入是否保留；失败重试是否合理；键盘焦点是否可达；是否为简单预约引入多余功能。

## C · 数据密集页面

> 为三家门店设计 375px 手机经营日报 HTML。A 店销售 120000、目标 150000、同比 -8%、订单 60；B 店销售 95000、目标 100000、同比 +12%、订单 50；C 店销售 70000、目标 100000、同比 0%、订单 35。展示整体结果与门店比较，支持筛选并保持汇总口径一致。币种 CNY，日期为演示日期。不得凭空补充趋势、库存或渠道数据。品牌未指定，自主推导设计。

检查：总销售 285000、总目标 350000；达成率按汇总计算而非平均门店百分比；无去年销售额时不能简单平均同比冒充整体同比；门店横向比较容易；无虚构图表。

## 记录方法

每项分别记录通过、失败、未验证及证据：业务正确性、任务完成、布局与文字、交互恢复、视觉适配、范围控制。保存原始输出、截图、必要修正及操作次数。审美判断附具体区域与理由，不合并成无依据总分。

可用 `scripts/check-mobile.cjs` 收集 HTML 的初步测量；还需人工/Agent 看截图并实际操作。比较结果不得只挑胜出的样本；至少保留每题的原始尝试。若评审者已见对照方案，标明非盲评。只有跨任务重复出现的问题才进入通用规则，任务数据和样式留在案例中。
