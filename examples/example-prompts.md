
## 局部修改，不重做整套设计

```text
使用 $ui-app-skill，把现有记账 App 账单页的筛选入口改得更清晰。保留品牌、导航和其余页面，实现筛选条件选择、应用和重置。
```

验收：修改集中在筛选相关区域；应用后列表实际变化；重置恢复全部结果；不会重新研究一整套竞品或改掉已接受的视觉系统。

## 首次试跑：中文阅读记录 App

```text
使用 $ui-app-skill，为一款面向中文读者的阅读记录 App 设计书架、书籍详情和阅读记录表单，生成可交互 HTML 原型。视觉方向是温暖、克制、有书籍质感；使用真实长度的中文书名和笔记。先完成代表性页面并检查，再扩展其余页面。支持从书架进入详情、记录阅读进度、保存后更新进度和返回书架；不需要账号和后端。
```

验收：书架、详情、表单具有适合各自任务的结构；保存确实更新进度；长书名不会挤掉操作；窄屏和大文字下操作可达；交付含可打开原型、关键屏预览和真实验证范围。

## 参考图转译

```text
使用 $ui-app-skill，根据我提供的参考图设计一款播客 App 的发现页和节目详情页。借鉴文字层级与图片处理，使用原创品牌和内容，做可点击 HTML 原型。
```

验收：说明实际从参考中观察到的规则；不复制品牌和整屏构图；不把静态图片中的推测写成已验证交互；发现页能够进入节目详情。

## 其他案例的验收重点

- 从零设计：记录可保存，趋势页对应更新，页面共享视觉规则。
- 工具类 App：导入、处理中、结果和失败恢复构成可演示闭环，明确哪些文件处理行为为模拟。
- 双平台适配：品牌一致，并说明实际实现或仅标注的系统行为差异；不能只换图标就声称完成双平台适配。
- 设计走查：问题有具体位置、证据、影响和修正；只凭截图无法判断的交互应标为待验证。
- 作品集优化：展示内容有产品逻辑支撑，不虚构用户研究和业务指标。

## 布局回归：文件工具首页

```text
使用 $ui-app-skill，设计文件扫描与整理工具首页。手机预览最大宽度 430px，背景 #FAF9F6，主操作色 #BD411D，文字 #292B29。底部导航固定吸底，默认文件行不超过 64px，缩略图不超过 32×40px。常规文字下 Hero 在 390px 宽时不超过 200px、320px 宽时不超过 180px；文字放大时优先保证可读性和操作可达。支持搜索、分类、收藏、时间排序、重命名、示例归档、本地图片/PDF 导入与示例文字下载。
```

验收：执行 320px、390px 和 320px＋130% 实际文字放大的浏览器检查，截图并测量。滚动到底后最后一项距固定导航至少 16px；主体留白至少为实测导航高度加 20px。无横向溢出、无按钮文字裁切，点击区域至少 44×44 CSS px。分别验证交互、持久化和错误恢复；扫描与 OCR 模拟边界清楚。此案例的颜色和尺寸只用于该项目，不作为所有 App 的固定风格。

## 手机端运营页与位图主视觉

```text
使用 $ui-app-skill，为阅读 App 设计一张“秋日阅读计划”活动首页。根据页面调性调用当前可用的 GPT 生图能力，生成有纸张质感的位图主视觉，不用 SVG 或 CSS 插画替代。标题、活动说明和参与按钮保留为真实页面文字，输出可交互 HTML。
```

验收：生成素材保存在项目内；图片与页面配色、留白及文字层级协调；320px 和 390px 下主体裁切合理；按钮可操作；准确说明实际可确认的生图工具或模型，不虚构“最新型号”。

## 对话内原型与联动状态

```text
使用 $ui-app-skill，在对话内做一个手机端经营分析原型，不要 Figma 或独立网站。包含最近 7/30 天筛选、收入/订单切换、趋势和渠道两个联动视图。使用确定性的演示数据，点击渠道筛选趋势，点击日期查看当天渠道构成，再次点击取消。
```

验收：按宿主的内联输出格式呈现；可触控操作且不依赖 hover；相同筛选下汇总和图表使用同一数据范围；切换周期后失效日期选择清除；明确模拟数据；不声称使用了无法确认的产品功能或原生组件。

## 从原型到开发实现

```text
使用 $ui-app-skill，把我提供的手机端 HTML 原型接入当前 React Native 工程。保留已有路由、状态管理和组件库，实现查看列表、进入详情、编辑并保存后同步更新列表。数据暂用本地 fixture，交付可运行的工程代码和简短开发说明。
```

验收：先检查现有工程；复用真实组件；移除或替换 HTML/宿主专属依赖；保存后相关页面一致；保留失败恢复所需输入；运行环境支持的检查，说明未验证原生行为；不止交付截图、零散代码或待办清单。

## 原生局部修复

```text
使用 $ui-app-skill，只修现有 Android Flutter 表单的键盘遮挡问题，保留视觉、路由和状态管理。不要重新设计其他页面。
```

验收：检查实际滚动与键盘 inset，修复受影响布局；检查输入框、提交按钮、返回/关闭键盘后的状态；不换框架、不引入 Figma、不研究整套竞品；没有设备环境时明确原生键盘验证缺口。

```text
使用 $ui-app-skill，为中文阅读工具设计书架、详情、记录三屏可编辑设计稿。保留真实文本和复用组件，我没有指定设计工具。
```

## 长报表转为移动端业绩页

```text
使用 $ui-app-skill 优化这张门店顾问业绩页。现在太像后台报表，希望有 App 的浏览体验。保留业务数据与品牌，不增加未提供的目标或趋势，给我可操作的页面预览。
```

验收：先记录并自评视觉方案；首屏能理解个人、周期与主要业绩；按用户任务组织摘要和明细，必要信息可达；实际操作展开/收起与日期范围；未知数据明确展示缺口；交付可运行预览及截图，不能只用一张生成图片替代。原稿数值不一致应标明口径待核对，不擅自修造数据。

## 品牌局部优化与交付边界

```text
使用 $ui-app-skill 优化这张已有移动端销售页面。只调整文字层级、间距和明细阅读，保留现有配色和导航。给我一张静态效果图。
```

验收：沿用用户明确选择的静态格式；局部检查相关视觉决策，保持配色与导航；不强制新品牌、深蓝金色、三项摘要或额外详情页；图中的数值与业务文案完整，准确说明交互未验证。
