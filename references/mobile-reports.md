# Mobile reports

Recompose for the target phone width while preserving metric meanings, units, periods, comparison bases, and necessary details. Inventory the source sections and map each to the mobile view or a discoverable detail route. Unreadable source values stay explicitly unavailable; do not invent precision or replace missing data with plausible numbers.

Choose structures from the reading task. Possible treatments include grouped summary metrics, aligned columns for multi-field comparison, ranked bars for magnitude, lines for time, and labeled part-to-whole charts for composition; select only what the actual data and task support, without prescribing a fixed page sequence or KPI grid. Cards are useful grouping tools, not the default representation of every row. Preserve meaningful comparisons when stacking; use labeled horizontal scrolling for genuinely wide detail tables rather than shrinking text.

Give overview and detail different density. Chart area must carry information: align legends and values near their marks, identify units and series, and distinguish missing values from zero. Do not add a chart merely to imitate a reference. A short page or fewer cards is not itself a quality gain.

At the requested width, inspect first viewport and all sections: headers align with values; units and deltas belong to the correct metric; chart labels and totals match data; ranks remain comparable; text remains readable; empty space has a purpose; detail controls work. Check narrow width and enlarged text using the HTML layout procedure. Record source omissions separately from runtime passes. Compare references at equal CSS width according to their assigned role; borrow structure only when the task calls for it. Evaluate readability at actual phone size, separately from overflow measurements. Define text roles from the platform and audience; for ordinary mobile Web, 14–16 CSS px body text and 12–13 px secondary labels are useful starting points, not universal requirements. Dense reports may need a different scale, but critical values, units and comparisons must remain readable without zoom. Reduce redundant content or expose secondary details before compressing text. Keep exact project values in project notes.
